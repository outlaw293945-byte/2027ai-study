# ブログ記事作成スキル

ユーザーの「ブログ記事を書いて」「〇〇について記事/読み物を作って」というリクエストで、専門家チーム（サブエージェント）を分担させて記事を1本仕上げる。

## 手順

### 1. ヒアリング（勝手に決めず、足りない情報だけ聞く）
次を確認する。すでに分かっているものは聞き直さない。
- テーマ（何について書くか）
- 読者（誰に向けて。初心者向けなら専門用語に説明を添える）
- 長さの目安（例：読み切り3分）
- トーン（やさしく／かっちり／など）
- 保存場所とファイル名

### 2. 人数を決める（目的から逆算）
- 基本形は3人（構成 → 執筆 → 磨き）。
- しっかりした成果物は5人（リサーチ → 構成 → 冒頭 → 執筆 → 磨き）。
- 目的が特殊なら役割を入れ替える（例：数字が主役なら「試算担当」を独立させる）。
- 迷ったらユーザーに人数を任せてもらい、こちらで判断して伝える。

### 3. 専門家チームで分担（サブエージェントを順番に呼ぶ）
前の担当の成果を次の担当に渡すリレー形式で進める。
1. リサーチ担当：キーメッセージと要点、たとえ話の切り口を整理（本文は書かない）
2. 構成担当：タイトル案＋見出し＋各項目に書くこと。表や注意書きの配置も指定
3. 冒頭担当：読者を引き込む書き出し（200〜300字目安）
4. 執筆担当：構成と冒頭をもとに本文を完成
5. 磨き担当：誤字・流れ・トーン・分かりにくい表現を最終調整

### 4. お金・健康など影響の大きい数字を扱う場合
- 数字は正確に計算し、前提（利回り・期間など）を明記する。
- 「一定の条件を仮定した目安であり、将来を保証しない」と必ず添える。
- 特定の誰かを責める書き方にしない。前向き・誠実に。

### 5. 保存して確認
- 完成した記事をMarkdownで保存（上書きしない。同名があれば別名にする）。
- `open` コマンドでファイルを開いて、ユーザーに確認してもらう。
- 記事末尾に「このスキルで作った」注記を1行入れてよい。

## トーンの共通ルール（このフォルダの CLAUDE.md に従う）
- 日本語で、専門用語には一言説明を添える。
- 小さく区切って進め、勝手にファイルを削除・上書きしない。
